# 设计文档：移除 sei-wasm 模块

## 背景
AESC Chain 继承自 Sei Protocol，原本支持 EVM 和 CosmWasm 双智能合约运行时。当前决策是移除 CosmWasm 支持，专注于 EVM 生态。

### 约束
- 必须保持 EVM 功能完整性
- 必须保持 Cosmos SDK 模块接口（IBC 兼容）
- 必须确保编译通过且测试可运行

### 利益相关者
- 开发团队：减少维护负担
- 验证者：减小节点软件体积

## 目标 / 非目标

### 目标
- 完全移除 CosmWasm 运行时代码
- 清理所有 wasm 相关依赖
- 确保 EVM 功能不受影响
- 代码库可成功编译
- 现有 EVM 测试全部通过

### 非目标
- 不需要迁移现有 wasm 合约（假设没有生产环境合约）
- 不修改 EVM 功能
- 不修改共识机制

## 决策

### 移除策略：分层递进式清理

**决策理由：** 采用从外到内、从依赖到核心的顺序移除，便于在每一步验证编译状态。

**执行顺序：**
1. **阶段一：移除独立模块** - 测试/示例/合约文件
2. **阶段二：移除业务代码** - wasmbinding、aclmapping/wasm、precompiles/wasmd
3. **阶段三：清理核心依赖** - app/*.go 中的 wasm 引用
4. **阶段四：更新构建配置** - go.mod、go.work
5. **阶段五：删除子模块目录** - sei-wasmd、sei-wasmvm
6. **阶段六：验证和文档更新**

### 考虑的替代方案

1. **条件编译** - 使用 build tags 禁用 wasm
   - 优点：可以保留代码以备将来使用
   - 缺点：增加复杂度，不符合"彻底移除"的目标
   - **未采用**

2. **保留空接口** - 只移除实现，保留接口
   - 优点：更容易将来恢复
   - 缺点：遗留无用代码，产生混淆
   - **未采用**

## 风险 / 权衡

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| EVM 功能意外受损 | 高 | 每阶段后运行 EVM 测试 |
| 编译失败 | 中 | 分阶段移除，每步验证 |
| 遗漏隐藏依赖 | 中 | 使用 grep 全面搜索 |
| 回滚困难 | 低 | 在新分支操作，保留原分支 |

## 迁移计划

### 步骤
1. 切换到新分支 `remove-wasm`
2. 按阶段执行移除
3. 每阶段后运行 `go build ./...` 验证
4. 运行 EVM 相关测试
5. 运行完整测试套件（预期 wasm 测试失败/被移除）
6. 代码审查
7. 合并到主分支

### 回滚
- 如果发现问题，直接切回原分支
- 如果已合并，使用 git revert 或从备份分支恢复
